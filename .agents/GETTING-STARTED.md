# Харнесс агентов TechCon — быстрый старт

Этот файл раздаётся в каждый репозиторий `techcon_*` как `.agents/GETTING-STARTED.md`.
Он самодостаточен: всё, что нужно, чтобы поставить и проверить харнесс, — здесь, без
переходов в другой репозиторий. Полный технический справочник (все команды, все правила,
все дополнения) — соседний файл `.agents/REFERENCE.md` в этом же репозитории.

## Часть 1. Для человека: что это и зачем

### Что это в двух словах

Харнесс — общий набор защит и подсказок для ИИ-помощника, который пишет код в
репозиториях TechCon. Он не даёт помощнику выполнить опасную команду (например, слить
изменения в обход проверок или вывести пароль в переписку целиком) и напоминает про то,
что легко забыть (тесты, язык документации, фирменные цвета интерфейса). Часть правил
раньше существовала только текстом в `AGENTS.md` — помощник мог их не заметить. Харнесс
переводит важную часть правил в код, который реально срабатывает.

### Зачем это вам

Без харнесса ограничение существует только как договорённость: помощник может случайно
нарушить её, если не обратит внимание на нужный абзац документа. С харнессом опасное
действие либо прямо запрещено, либо помощник получает явное напоминание в процессе
работы — не после того, как что-то уже случилось.

### Три сценария — какой ваш

Харнесс поддерживает два независимых ИИ-помощника — Claude Code и Codex CLI. У вас
может быть только один из них или оба сразу:

| сценарий | у вас установлен | что делать |
|---|---|---|
| **только Codex** | `codex` (Codex CLI), Claude Code не используете | раздел «Установка — только Codex» |
| **только Claude Code** | `claude` (Claude Code), Codex CLI не используете | раздел «Установка — только Claude Code» |
| **оба раздельно или вместе** | и `codex`, и `claude` | раздел «Установка — оба помощника» |

Узнать, что у вас установлено: `which claude codex` в терминале — что нашлось, то и
установлено.

Раздельно и совместно в третьем сценарии не различаются на уровне установки: харнесс
ставит защиту для каждого помощника независимо, и то, работаете вы с ними по очереди в
одном репозитории или параллельно в разных, ничего в шагах установки не меняет.

## Часть 2. Установка

Вам понадобятся: `git`, `python3` версии 3.11 и выше, `ssh-keygen`, права `sudo` на
машине. Установку выполняете **вы сами, в своём терминале** — ИИ-помощник её не
запускает: пароль `sudo` он вводить не может и не должен.

Не запускайте команды вида «скачать скрипт из сети и сразу выполнить». Установка идёт
из клона репозитория `techcon_agent_harness`, у которого вы сами проверили подпись
выпуска.

### Установка — только Codex

1. Получите у владельца харнесса закреплённый хеш коммита выпуска, канал (`canary` или
   `stable`) и идентичность подписи. Без этих трёх значений не начинайте.
2. Клонируйте харнесс и перейдите на закреплённый коммит:

   ```bash
   git clone git@github.com:techcon-ml/techcon_agent_harness.git ~/techcon_agent_harness
   cd ~/techcon_agent_harness
   git checkout <закреплённый-хеш-коммита>
   git rev-parse HEAD   # должен вывести ровно тот хеш, что дал владелец
   ```

3. Проверьте подпись выпуска без установки (по умолчанию `install.sh` ничего не пишет):

   ```bash
   ./installer/install.sh \
     --backup-root /var/lib/techcon-harness/backups \
     --session-id "install-$(date +%Y%m%d-%H%M%S)" \
     --source-repo-root . --staging-dir /tmp/techcon-harness-staging \
     --manifest <MANIFEST> --signature <MANIFEST.sig> \
     --channel <канал> --identity <идентичность-подписавшего> --repo-root . \
     --harness-root /opt/techcon-harness --claude-settings-dest ~/.claude/settings.json
   ```

   Запомните `--session-id` — по нему делается откат. Ожидается код выхода 0.
4. Повторите ту же команду с флагом `--apply`. Установщик спросит пароль `sudo` — это
   нормально: машинный слой ставится в `/opt/techcon-harness`, каталог остаётся
   root-owned, чтобы сам помощник не мог его изменить.
5. Машинный слой Codex — файл `/etc/codex/requirements.toml`; установщик прописывает
   его тем же шагом. Для варианта «только Codex» `--claude-settings-dest` в команде
   выше можно опустить, если Claude Code вы не используете вовсе.
6. Откройте новую сессию Codex CLI и проверьте установку (раздел «Проверка» ниже).

### Установка — только Claude Code

Шаги 1–4 те же, что для Codex (клонирование, проверка подписи, `--apply`), но обязателен
флаг `--claude-settings-dest ~/.claude/settings.json` — установщик **сливает** в него
ключ `hooks`, а не перезаписывает файл: остальные ваши ключи и чужие хуки остаются на
месте. Перед записью делается резервная копия. После установки откройте новую сессию
Claude Code и проверьте установку.

### Установка — оба помощника

Выполните шаги «только Codex» и «только Claude Code» одной и той же командой
`install.sh --apply`, передав оба назначения:
`--claude-settings-dest ~/.claude/settings.json` для Claude Code — машинный слой Codex
(`/etc/codex/requirements.toml`) устанавливается той же командой без дополнительного
флага. Один прогон установщика ставит защиту для обоих помощников сразу; повторный
прогон второй раз не требуется.

### Если у вас macOS

**Не проверено живьём** — установка на macOS ни разу не выполнялась ни владельцем
харнесса, ни коллегами (в организации нет macOS-машины для этой проверки). Шаги выше
теоретически применимы: установщик написан переносимо (`shutil`/`pathlib`, без
Linux-специфичных вызовов). Известное отличие — пути машинного слоя на macOS
(`/Library/Application Support/ClaudeCode/`, `/private/etc/codex`) не подтверждены
живым запуском. **Если вы первый коллега, который ставит харнесс на macOS — сообщите
владельцу харнесса результат** (что сработало, что нет) независимо от исхода; подробный
чеклист для этого случая — раздел «macOS» в `.agents/REFERENCE.md`.

## Часть 3. Проверка — развёрнут ли харнесс

Одна команда, которая читает только локальные файлы машины и ничего не исполняет из
репозитория:

```bash
python3 /opt/techcon-harness/cli/doctor_machine.py --machine
```

Ответ — один из трёх:

```text
развёрнуто: да
хуки Claude Code: да (~/.claude/settings.json)
машинные файлы: да (/opt/techcon-harness/hooks/run.py)
требования Codex: да (/etc/codex/requirements.toml)
```

```text
развёрнуто: нет
машинные файлы: нет (/opt/techcon-harness/hooks/run.py не найден)
что сделать: выполните шаги из .agents/GETTING-STARTED.md
```

Если строка Codex или Claude Code отсутствует у вас намеренно (сценарий «только
Codex»/«только Claude Code») — это не ошибка, читайте вердикт по тому помощнику,
который вы действительно ставили.

## Часть 4. Дополнения — что ставить, что необязательно

Полный каталог с объяснением каждого пункта — раздел «Полный каталог дополнений» в
`.agents/REFERENCE.md` этого же репозитория. Ниже — самое важное коротко, без перехода
куда-либо ещё:

| дополнение | зачем | Codex | Claude Code | обязательно? |
|---|---|---|---|---|
| `ccusage` | счётчик расхода токенов и стоимости | да | да | обязательно |
| нативный OTel-экспорт | те же метрики штатными средствами помощника | да (`[otel]`) | да | обязательно |
| строка состояния (`statusLine` / `tui.status_line`) | видно контекст/стоимость прямо в терминале | да | да | обязательно |
| нативные уведомления | сигнал, когда помощнику нужен ваш ответ | да (`tui.notifications`) | да | обязательно |
| нативные worktree / субагенты | параллельная работа без гонок за один чекаут | да | да (`--worktree`) | обязательно |
| Serena (MCP) | понимание структуры кода без перечитывания всего репозитория | да | да | обязательно |
| GitHub MCP Server (read-only) | помощник видит PR/issues без ручного копирования | да | да | обязательно |
| Anthropic Sandbox Runtime | ограничение файловой/сетевой песочницы уровня ОС | да | да | обязательно |
| официальный формат `AGENTS.md` | единый файл правил читают оба помощника | да | да | обязательно |
| CodexBar / claude-powerline | расширенная статусная строка | да | да | по желанию |
| `workmux` / `gtr` | управление несколькими worktree из одного терминала | да | да | по желанию |
| Playwright MCP, Exa MCP | автоматизация браузера, веб-поиск для агента | да | да | по желанию (по проекту) |

Установка дополнения с явно закреплённой командой:

```bash
python3 -m cli.techcon_harness addons list                 # что вообще есть в каталоге
python3 -m cli.techcon_harness addons install <name> --dry-run   # план без изменений
python3 -m cli.techcon_harness addons install <name> --yes       # реальная установка
```

Без `--yes` команда `install` только печатает план и ничего не меняет.

## Часть 5. Типовой пайплайн задачи

1. **Возьмите задачу.** Задача из Linear или локальная формулировка — помощнику нужен
   ясный критерий «готово», не только описание проблемы.
2. **Поработайте с помощником.** Опишите задачу, дайте помощнику прочитать нужные
   файлы, проверьте его план перед тем, как он начнёт массово редактировать код —
   особенно для задач, затрагивающих несколько файлов сразу.
3. **Прогоните проверки локально до коммита.** Тесты и линт, насколько позволяет
   оборудование — раннеры CI не бесплатны, не используйте их как первый прогон.
4. **Закоммитьте.** Формат заголовка — Conventional Commits
   (`<type>(<scope>): <summary>`), например `fix(hooks): устранить ложное срабатывание
   language-check`. Список допустимых `<type>` закрыт; подробности и привязка к задаче
   Linear — скилл `techcon-git-workflow`, раздел «Формат коммитов» в
   `.agents/REFERENCE.md`.
5. **Откройте запрос на слияние.** Если правило репозитория требует ветку от `develop`,
   а не от `main` — следуйте ему; харнесс сам по себе веток не создаёт и слияние не выполняет.
6. **Если хук что-то заблокировал** — прочитайте сообщение (в нём названы правило и
   причина), не обходите его; если блок ложный — отключите именно это правило командой
   `hook disable` (раздел «Хуки и правила» в `.agents/REFERENCE.md`) и сообщите
   владельцу харнесса, какая команда была заблокирована.
