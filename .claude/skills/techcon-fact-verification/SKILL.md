# Факт-проверка — документ никогда не источник факта о мире

## Зачем

Зелёные тесты доказывают, что код делает то, что проверяет тест. Они **не** доказывают
утверждений о мире вокруг кода: какой хост — цель деплоя, какое значение флага сейчас
действует, какой репозиторий чем владеет, смержен ли PR. На практике неоднократно
встречались случаи, где именно такие факты оказывались неверны при полностью зелёной
кодовой части — потому что источником был устаревший документ, а не живой замер.

## Единственное жёсткое правило

**Другой документ не является источником факта о мире.** Он мог скопировать то же
устаревшее значение, и это не будет заметно по его виду — документ выглядит одинаково
авторитетно, актуален он или нет. Если для проверки утверждения вы открыли `.md`, README
или заметку — проверка не состоялась. Открывать документ можно только для того, чтобы
узнать, ГДЕ искать живой источник (путь к конфигу, адрес хоста, номер PR) — не для того,
чтобы взять из него сам факт.

## Маршрутная таблица примеров

| Утверждение о… | Живой источник |
|---|---|
| статус PR, смержен ли | `gh pr view <N> --json state,mergedAt` |
| что реально в ветке | `git -C <repo> log --oneline -5 <branch>` |
| значение конфиг-флага | сам конфиг **на хосте**, где он реально читается: `ssh <host> "cat <path>"` |
| состояние ВМ, диска, сети | `yc compute instance get`, `yc vpc security-group get` (или аналог облачного провайдера) |
| работает ли сервис | `curl -s <host>/health`, `ssh <host> "systemctl status <svc>"` |
| что смонтировано в контейнер | `docker inspect <ctr> --format '{{json .Mounts}}'` |
| текущая владелец/статус задачи | трекер задач напрямую (Linear/Jira API), не пересказ в чате или markdown |
| число коммитов/расхождение веток | `git rev-list --left-right --count origin/main...origin/develop` на актуальном чекауте |

Таблица — не исчерпывающий список, а образец. Для утверждения, которого в ней нет,
нужно придумать независимый живой источник и назвать его явно, прежде чем проверять.

## Порядок

1. Выписать утверждение одной строкой, как оно прозвучит в отчёте.
2. Найти или придумать живой источник — команду или API-вызов, а не файл с чужим выводом.
3. Выполнить, привести **наблюдаемый вывод** (текст команды/ответа), не пересказ своими словами.
4. Совпало с тем, что предполагалось, — записать вместе с командой, которой проверено.
   Не совпало — исправить утверждение, а не источник, из которого оно взято.

## Осторожно: облачные права

`PermissionDenied` сразу после того, как роль/право только что выданы, — часто лаг
распространения прав, а не реальная нехватка доступа. Прежде чем заключать «доступа нет»,
повторить проверку через ≥30–60 секунд. Отброшенную гипотезу лага стоит явно зафиксировать
в отчёте о диагностике, а не молча отбросить.

## Осторожно: секреты

Ни одна проверка не должна печатать секрет в вывод — он попадёт в транскрипт и логи, а
транскрипт обычно не считается защищённым хранилищем секретов. Не выполнять команды вида
«вывести все переменные окружения без фильтра», «вывести токен доступа», «прочитать секрет
целиком без jq-фильтра по нужному полю» — токен, попавший на экран один раз, нужно считать
скомпрометированным независимо от того, был ли он потом использован куда-то ещё.

## Что проверка НЕ закрывает

Факт-проверка подтверждает конкретное утверждение, но не заменяет весь исход работы.
Проверенный факт «сервис жив» не означает, что задача закрыта — закрытие задачи требует
доведения состояния от плохого к хорошему и фиксации этого перехода, факт-проверка — лишь
один из инструментов, которым это подтверждается.
