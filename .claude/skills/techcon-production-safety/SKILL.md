# Production safety

Операции, необратимо влияющие на боевое состояние (прод, облако, БД,
релиз), требуют явного подтверждения человека перед выполнением — не
после.

## Что считается gated-операцией

- Мутации облака: `yc compute start/stop/reboot`, `terraform apply`,
  изменение сетевых правил, снятие защиты с боевых ресурсов.
- Изменения БД: миграции, `DELETE`/`DROP`/`TRUNCATE`, прямые правки
  продовых данных.
- Релизы: деплой, промоушн ветки в боевую (`main`/`prod`/аналог), мердж
  в защищённую ветку, откат боевого поведения.
- Любая команда, которую нельзя тривиально отменить, если она пошла не
  так.

## Что делать

1. Прежде чем спрашивать подтверждение — собери контекст сам: прочитай
   локальные файлы, конфиги, историю git, состояние CI. Не перекладывай
   на человека работу, которую можно сделать автономно.
2. Оцени blast radius: что именно меняется, кого/что затронет, можно ли
   это откатить и как.
3. Запроси подтверждение явным текстом, включающим:
   - команду/действие дословно;
   - цель (какой ресурс/окружение/ветка);
   - blast radius (что сломается при ошибке);
   - backup/checkpoint (что сохранено перед изменением);
   - план отката;
   - план проверки, что изменение сработало.
4. Выполняй gated-операцию только после явного «да» от человека —
   не по умолчанию, не по истечении паузы, не потому что план «выглядит
   безопасным».
5. Локальные правки кода и прогон тестов остаются автономными, пока они
   не затрагивают живое/боевое состояние напрямую.

## Секреты

- Никогда не печатай в вывод/лог секреты, токены, приватные ключи,
  пароли, файлы аутентификации — ни целиком, ни фрагментом, который их
  выдаёт (например, `redis://:password@host` целиком).
- Если нужно проверить наличие секрета — проверяй факт наличия (grep по
  имени переменной), не его значение.

## Отказ — штатный исход

Если запрошенное действие нарушает эти правила (например, просят
смержить без прохождения CI, снять prod-защиту без подтверждения,
запустить необратимую операцию без плана отката) — откажи и предложи
корректный путь (запросить подтверждение, дождаться зелёного CI,
сначала сделать checkpoint). Отказ — не конфликт, а ожидаемое поведение.
