# Экономия CI — не гонять раннеры ради того, что проверяется локально

> Вариант B решения владельца по `docs/proposals/2026-09-28-ci-economy.md` (вариант D: A+B
> сейчас, C — хук-совет — отложен).

## Когда

Перед каждым `git push`, `gh run rerun`, `gh workflow run`, а также перед открытием PR.

## Зачем

Прогоны идут на собственных раннерах TechCon (около 30 тыс. ₽ в месяц). Медиана тяжёлого задания
0,5 минуты, а подъём пода дороже самой работы. За 24–28.09.2026 было 1041 PR-прогон на 233 ветки,
а на ветках-лидерах по 50, 30 и 17 прогонов. Каждый пуш запускает 3–5 воркфлоу.

## Шаги

1. **Локальные проверки до пуша.** Прогони то, что прогонит CI, теми средствами, что есть в
   репозитории:
   - `pre-commit run --all-files` (или по изменённым файлам), если есть `.pre-commit-config.yaml`;
   - `make ci-local` или `scripts/ci_local.sh`, если есть (пример `techcon_passports`);
   - `scripts/pytest_with_peers.sh` в `techcon_hub` (голый `pytest` без соседних клонов там
     роняет тесты реестра);
   - иначе — `uv run pytest -q` и линтер из `pyproject.toml`.
   Команду, которую нельзя прогнать локально (нужен VPC, секрет, GPU), назови в описании PR явно.
2. **Одна-две итерации самокритики диффа** до пуша — по скиллу `techcon-self-critique`
   (`git diff origin/<base>...HEAD`).
3. **Пуш пачкой.** Копи логически связанные коммиты локально и отправляй одним пушем. Каждый
   пуш — это 3–5 воркфлоу.
4. **Красный CI — сначала лог, потом действие.** `gh run view <id> --log-failed` (не полный
   `--log`: он забивает `/tmp`). Разбери причину:
   - ошибка в коде — чини локально, прогони локальную проверку, потом пуш;
   - инфраструктура (тайм-аут `checkout`, загрузка экшенов, раннер не вышел online) — один
     осмысленный перезапуск только упавших заданий (`gh run rerun <id> --failed`), и если снова
     инфраструктура — остановись и оформи симптом, а не перезапускай по кругу.
5. **Очередь не забивать.** Если в репозитории нет `concurrency: cancel-in-progress` для PR-
   воркфлоу, а ты пушишь в ветку с идущим прогоном — предложи добавить его в отдельном PR.

## Запреты

- Не пушить «проверить в CI», пока локальная проверка не прогнана или не объяснено, почему она
  невозможна.
- Не перезапускать весь прогон целиком, если упали отдельные задания.
- Не перезапускать повторно без нового знания о причине (пример 21.09.2026: три перезапуска
  подряд во время деградации сети, а локальный `make ci-local` был 11 из 11 зелёных).
- Не добавлять в воркфлоу `ubuntu-latest`/`macos-latest` вместо self-hosted раннеров: биллинг
  GitHub-hosted у организации исчерпан (Р-21, 15.09.2026), это задевает все репозитории.

## Результат

В описании PR или в отчёте сессии — строка «Локально: <команда> — зелёная» (или почему локально
нельзя). Число пушей на PR — единицы, а не десятки. Перезапуск CI — только с названной причиной
из лога.
