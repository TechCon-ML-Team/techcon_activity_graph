# Итог сессии и разбор прошлой сессии

Два назначения, один скилл: написать короткий итог, который читается за минуту без
открытия других файлов, и по журналам поднять ход прошлой сессии, когда итога нет или
ему нельзя верить.

## Когда

- Сессия подходит к концу, и человеку нужно понять, что произошло, не читая переписку.
- Итог нужен в описание PR, комментарий к задаче или сообщение коллеге.
- Спрашивают «что мы делали в прошлый вторник», «почему сессия встала», «сколько она стоила».

## Итог: три строки

```
Сделал: <что изменено и где — с номером PR, коммита или задачи>
Проверил: <чем подтверждено — команда и результат, не «должно работать»>
Осталось: <что не сделано, кто и что должен сделать дальше>
```

Всё вместе — не больше 600 знаков (лимит из стандарта описания задач). Не влезает —
агрегируй («4 репозитория», а не список), лишнее уводи в PR или задачу.

### Правила

1. **Только то, что проверено в этой сессии.** Строка «Проверил» содержит команду и её
   наблюдаемый итог. Не проверял — так и пиши: «не проверял: …». Пересказ чужого отчёта
   проверкой не считается.
2. **Число вместо «несколько».** «3 теста красные», а не «есть падения».
3. **Каждое действие — глагол и адресат.** «Осталось: владельцу выдать право на бакет»,
   а не «вопрос прав».
4. **Отказы и обходы — в «Осталось».** Пропущенный гейт, отложенная проверка, ручная
   правка вместо штатного пути — не прячь, это то, ради чего итог читают.
5. **Без внутреннего жаргона.** Читатель не обязан знать названия ваших файлов и
   инструментов: пиши «список задач», «решение по фазе», а не имена артефактов.
6. **Ссылки на живое.** PR, коммит, задача — идентификатор; путь к личному каталогу
   на чьей-то машине — никогда.

### Пример

```
Сделал: чинил падение бэкапа сервиса отчётов — перезапуск задачи, PR #412 (лимит времени 30 мин).
Проверил: ручной запуск бэкапа завершился за 11 мин, код 0; тесты пакета — 84 из 84.
Осталось: не проверял ночной прогон — посмотреть завтра в 04:00; причину зависания процесса не нашли.
```

## Если итога слишком много для трёх строк

Когда работа объёмная (много репозиториев, решений, открытых вопросов), после трёх строк
допустим развёрнутый блок ≤60 строк: что нашли (факты по темам), что решили и почему, что
нужно сделать человеку, открытые вопросы, с чего начать следующую сессию. Три строки
остаются первыми и самодостаточными — блок ниже читают только те, кому мало. Шаблон блока
и разбор частых ошибок — `references/razvernutyj-itog.md`.

## Разбор прошлой сессии

Порядок такой: сначала найти сессию, потом восстановить ход, потом свести в итог.

1. **Найти.** Журналы сессий Claude Code лежат в домашнем каталоге пользователя:
   `.claude/projects/<путь рабочего каталога с заменой «/» на «-»>/<идентификатор>.jsonl`;
   рядом — подкаталоги с работой субагентов и с крупными результатами инструментов.
   Ищи по дате изменения файла и по характерной фразе (`grep -l "<фраза>"`).
2. **Восстановить ход.** Извлекай из журнала реплики и вызовы инструментов по порядку;
   различай главного агента и субагентов. Для каждого шага фиксируй: что попросили,
   что вызвали, чем кончилось.
3. **Найти места поломок.** Ошибки инструментов, отказы в правах, сжатия контекста,
   блокировки хуков — по каждому: где, что произошло, как справились или не справились.
4. **Оценить стоимость**, если журнал несёт учёт токенов: сумма по сообщениям, разбивка
   по модели. Нет учёта — так и сказать, не оценивать на глаз.
5. **Свести в три строки** по правилам выше и приложить разбор фактами.

Подробнее — команды поиска и подводные камни в `references/razbor-zhurnalov.md`.

## Запреты

- Не писать итог по памяти о чате: журнал, `git log`, вывод команд — единственные источники.
- Не переписывать чужой итог, не проверив его по журналу или `git`.
- Не печатать в итог или разбор секреты, токены, значения переменных окружения: журнал
  их может содержать, разбор — не повод их цитировать. Нашёл секрет в журнале — упомяни
  факт («в журнале виден токен») без значения и считай его скомпрометированным.
- Не выдавать разбор за полную картину, если часть журнала недоступна или обрезана.
- Не писать «сделано» там, где нет проверки: незакрытая проверка — это «Осталось».

## Результат

- Три строки «Сделал / Проверил / Осталось», ≤600 знаков, каждая утверждает только проверенное.
- При разборе прошлой сессии — сверх того список шагов, поломок и стоимости, у каждого
  вывода указан источник (файл журнала или команда).
