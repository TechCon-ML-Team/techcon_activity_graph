# Документация и язык по стандартам Техкона

## Когда

Любой текст, который прочтёт человек: README, `docs/`, справочник API, витрина, текст
интерфейса, описание задачи, отчёт, подпись диаграммы, комментарий в коде. Сначала
определи читателя, потом пиши: одна и та же фраза годится для разработчика и запрещена
для пользователя.

## Шаг 1. Определи аудиторию

| аудитория | поверхности | запрещено |
|---|---|---|
| пользователь | витрины, тексты интерфейса | адреса и имена машин, пути к файлам, хеши, имена очередей; вся лексика уровня `translate`; транслитерация |
| интегратор | справочник API (`docs/PUBLIC_API.md`), спецификация OpenAPI | внутренние поля (`fence_token`, `worker_id`), ключи Redis, имена хостов; лексика `translate`; допустимы устоявшиеся термины вроде «эндпоинт» |
| разработчик | `AGENTS.md`, `docs/`, код, runbook | лексика `translate`; описательный текст только по-русски; `transliterate_ok` разрешена |
| менеджмент | задачи трекера, отчёты | пути, хеши, номера запросов на слияние; переводится вся лексика словаря, включая `transliterate_ok` |

Внутрянка распознаётся образцом, а не смыслом: IP-адрес, имя хоста, путь вида
путь в домашний каталог, хеш из 7 и более шестнадцатеричных знаков, имя очереди. Нашёл образец в
тексте для пользователя или менеджмента — убери или замени эффектом для читателя.

## Шаг 2. Словарь: два уровня

- `translate` — переводится всегда, кроме технического слоя (код, runbook, справочник
  для разработчика).
- `transliterate_ok` — транслитерация допустима только в техническом слое; у
  пользователя и менеджмента переводится.

Кратко, полный список — `references/dictionary.md`:

| плохо | хорошо | уровень |
|---|---|---|
| деплой, задеплоить | выкатка, выкатить | translate |
| роллбэк | откат | translate |
| фикс, пофиксить | исправление, исправить | translate |
| тикет, ишью | задача | translate |
| мерж, смёржить | слияние, слить | translate |
| билд, релиз | сборка, выпуск | translate |
| бэкап | резервная копия | translate |
| ретрай | повтор | translate |
| пейлоад | тело запроса | translate |
| воркер | обработчик | transliterate_ok |
| таймаут | превышение времени ожидания | transliterate_ok |
| эндпоинт | эндпоинт | transliterate_ok |

Не переводим: имена полей JSON, HTTP-методы, идентификаторы в коде, названия технологий
(Docker, Redis, FastAPI), имена команд. Всё это — в обратных кавычках, правила языка
такой фрагмент не судят.

Если слова нет в словаре, а русский эквивалент есть и понятен — бери русский. Если
эквивалента нет и термин устоялся (`webhook`, `health-check`) — оставляй в техническом
слое и не тащи в пользовательский.

## Шаг 3. Общие запреты

1. **Mermaid.** Диаграммы только на D2 (шаг 5).
2. **Эмодзи в заголовках.** Заголовки строчные, без значков и без «Заголовка Каждого
   Слова С Большой Буквы».
3. **IP-адреса и имена машин** в тексте для пользователя, менеджмента и интегратора.
   Адрес и роль машины — в главном файле инфраструктуры, а не в памяти и не в
   документации.
4. **Внешние `src`, `href`, `@import`** в `.html`: страница автономна, при открытии не
   ходит в сеть. Явные ссылки для чтения (DOI, статья) разрешены.
5. **Пустые обороты («нейрослоп»).** Не пиши: `комплексный`, `бесшовный`, `мощный`,
   `robust`, `seamless`, `в современном мире`, `стоит отметить`, `играет ключевую роль`,
   `широкий спектр`, `революционный`. Слово из списка почти всегда заменяется числом,
   именем или удаляется целиком — см. примеры ниже.
6. **Секреты и домашние пути** в любом файле репозитория. Только `${ПЕРЕМЕННАЯ}`.

## Шаг 4. Справочник API (интегратор)

Формат и правила — `references/api-docs.md`. Главное:

- русский язык; `message` ошибок, `title`, `summary`, `description`, `Field(description=...)`
  и примеры — по-русски; `code` ошибки — `SCREAMING_SNAKE_CASE`;
- обязательны: версия `X.Y.Z`, таблица сред, матрица защиты (даже без аутентификации),
  формат ответов, коды ошибок, сквозной сценарий в конце;
- примеры — `curl` и Python `httpx`, пригодные для копирования как есть;
- пример ответа совпадает с реальным контрактом, а не с надеждами;
- никаких деталей реализации: очереди, владелец и токен захвата, идентификаторы
  обработчиков, модель видеокарты, экономика инфраструктуры. Называй только то, что
  меняется для читателя;
- страница-переходник или портал не становится вторым полным справочником, а
  ссылается на точный документ.

## Шаг 5. Диаграммы: только D2

- файлы `docs/diagrams/*.d2`, в каждом репозитории минимум `architecture.d2`;
  рендер в `.svg` через Kroki;
- подписи узлов и стрелок по-русски, заголовок строчный;
- начало файла: `vars: { d2-config: { theme-id: 200 } }` для тёмных диаграмм разработчика;
  цвета для тёмной диаграммы: фон `#1A1722`, граница `#3D3654`, акцент `#8075FF`,
  текст `#E8E6F0`, внешние системы `#2A2640`;
- UML-последовательности — PlantUML, схема БД — DBML; Mermaid не использовать нигде.

```d2
direction: right
service: {
  label: "Сервис паспортов"
  api: "HTTP-интерфейс"
  worker: "Обработчик задач"
}
клиент -> service.api: "запрос по HTTPS"
service.api -> service.worker: "очередь задач"
```

## Шаг 6. Интерфейс: светлая тема и токены

Правило одно: сервис для клиента — светлая тема; инструмент для разработчика и
эксплуатации — тёмная.

Токены светлой темы (клиентский слой):

| элемент | значение |
|---|---|
| фон страницы | `#FFFFFF` |
| текст | `#1E1B24`; вторичный `#4B4453`; приглушённый `#7A7286` |
| ссылки | `#8075FF` (обязательно; `#AEB8FE` на белом нечитаем) |
| поверхность карточки | `#F4F4F6`, граница `#E0DDE6` |
| основная кнопка | фон `#8075FF`, текст `#FFFFFF` |
| панель навигации | остаётся тёмной: `#4B4453`, нижняя линия `2px solid #8075FF` |
| метка успеха / предупреждения / ошибки (текст) | `#16A34A` / `#D97706` / `#DC2626` |

Цвета берём токенами (`var(--...)`), а не разбросанными шестнадцатеричными значениями.
Шрифт — Inter. `#D9ED92` — подсветка бренда, а не цвет предупреждения. Статус
передаётся текстом, а не только цветом; интерфейс работает с клавиатуры.

## Шаг 7. Задачи и отчёты (менеджмент)

Тело задачи — четыре блока целиком, читатель без доступа к репозиторию понимает суть:

```
## Что происходит      — наблюдаемый факт, 1–2 предложения, без причин и решений
## Почему это важно    — чей труд, деньги или риск; что будет, если не делать
## Что сделать         — конкретное действие, не «изучить» и не «оптимизировать»
## Как поймём, что готово — один проверяемый признак: команда, число, наблюдение
```

Ссылка на файл репозитория допустима отдельной строкой «Ссылка:» внизу, но не вместо
текста. Внешних людей называй ролями, а не именами.

Ответ при закрытии — один комментарий до 600 знаков, три строки:
`Сделал.` — что изменено; `Проверил.` — что предъявлено (команда, число; не «работает»);
`Осталось.` — «ничего» или один хвост.

## Шаг 8. Комментарии в коде

Комментарий отвечает на вопрос «почему», а не «что»: ограничение, неочевидный выбор,
ловушка. Не пиши историю ревью («по замечанию ревьюера», «исправлено в раунде 3»,
«раньше было иначе») — она живёт в истории коммитов и в `docs/history/`. Комментарий,
пересказывающий следующую строку, удаляй.

## Примеры «плохо → хорошо»

| плохо | хорошо |
|---|---|
| `## 🚀 Быстрый старт` | `## быстрый старт` |
| Комплексное и бесшовное решение для мощной обработки документов. | Сервис разбирает паспорт за 4 секунды и возвращает 12 полей. |
| Стоит отметить, что после деплоя воркер на машине с адресом из внутренней сети подхватывает задачу. | После выкатки обработчик берёт задачу из очереди; от вас действий не нужно. (для интегратора: без адреса и без описания очереди) |
| Пофиксили ретрай, релиз в пятницу. | Исправили повтор запроса, выпуск в пятницу. (менеджмент) |
| `flowchart LR` в блоке Mermaid | файл `architecture.d2` |
| `# нужно для ревью №2: Иван просил добавить` | `# ключ читаем дважды: первый ответ бывает пустым при холодном старте` |
| «Работает, проверено.» | «Проверил. `curl /health` вернул 200 и версию 1.4.2.» |

## Запреты

- Не правь текст под гейт, не поняв читателя: обход образца (адрес разбит точкой, слово
  латиницей) — тот же дефект, только скрытый.
- Не копируй справочник API в портал и в README: одна каноническая страница, остальное
  ссылки.
- Не подтверждай факт документом: адреса и роли машин, статус слияния — только живой
  замер (см. `techcon-fact-verification`).

## Результат

Текст соответствует аудитории; в нём нет Mermaid, эмодзи в заголовках, IP-адресов,
слов уровня `translate` вне технического слоя и пустых оборотов; диаграммы — D2;
интерфейс клиента светлый; комментарии кода объясняют «почему». Перед сдачей перечитай
текст глазами читателя из шага 1.
