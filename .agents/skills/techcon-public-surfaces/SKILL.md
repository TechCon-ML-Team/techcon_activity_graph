# Читательские поверхности — проверка перед публикацией

## Когда

Любое изменение того, что читает человек, не участвуя в разработке: README, отчёт, HTML-страница
для коллеги или клиента, сводка показателей, интерфейс ручной разметки. Не применять к
неизменяемым исходным артефактам (сырые выгрузки, замороженные снимки): их байты не правят
ради стиля, см. шаг 6.

## Зачем

Поверхность видна снаружи автору, и по ней читатель судит обо всей работе. Типичные сбои:
страница тянет шрифт или скрипт из сети и не открывается без интернета; статус передан только
цветом; в сводке число без знаменателя; поверхность есть, но никто не знает, кто за неё отвечает.
Ни один из них не ловят тесты кода.

## Шаги

1. **Определить поверхность по реестру.** Реестр поверхностей — один файл в репозитории
   (путь, назначение, владелец, кто читает, чем порождается). Если пути в реестре нет — сначала
   добавить строку, потом править. Публичный адрес без владельца и роли (основной, зеркало,
   устаревший псевдоним) не допускается.
2. **Менять первичный источник и генератор, затем производный HTML.** Правка готовой страницы
   руками исчезнет при следующей сборке.
3. **Числа.** Каждое число несёт источник, знаменатель, единицу и состояние неопределённости.
   Отсутствие данных не записывать нулём: пишется «нет данных».
4. **Технические требования к странице:**
   - светлая тема, русский текст;
   - автономность: файл открывается без сети, нет внешних шрифтов, скриптов, счётчиков и
     запросов при загрузке (обычные ссылки на литературу и источники разрешены — они не грузятся
     сами);
   - вся работа с клавиатуры: видимый фокус, логичный порядок Tab, нет действий только по мыши;
   - статус передаётся словом («выполнено», «ошибка», «ждёт»), цвет только дополняет;
   - контраст текста не ниже 4,5 к 1; ссылки на светлом фоне в тёмном оттенке, не в бледном.
5. **Различать в тексте** стадию конвейера, готовность данных и силу вывода, исполнение и
   независимую проверку, решение владельца и внешнюю зависимость. Смешение — ошибка поверхности,
   даже если каждая фраза верна.
6. **Неизменяемый исходник.** Не менять его байты. Рядом кладётся отдельный паспорт или
   производное представление с хешем SHA-256 оригинала.
7. **Интерфейс разметки** не показывает эталонные ответы, ответы модели, происхождение объекта и
   ответы другого разметчика. Варианты «не видно» и «неопределённо» допустимы и не блокируют.
8. **Секреты и адреса.** В поверхность не попадают ключи, внутренние адреса, домашние пути и
   имена сотрудников без нужды. Служебные машинные пути сервиса (метрики, схема API, страница
   документации) анонимно не отдаются, если владелец не принял обратное решение явно.
9. **Проверка перед сдачей:** прогнать проверку реестра и сборку поверхности; открыть файл
   с отключённой сетью; пройти страницу только клавишей Tab; поискать в файле `http` и
   `<script src`.
10. **Независимая рецензия.** Передать точный дифф (набор файлов с хешами) рецензенту, который
    не писал изменение. Самоодобрение автора не приёмка. Рецензент смотрит поверхность глазами
    читателя, а не сверяет её с тем, что задумал автор.

## Запреты

- Публиковать страницу с внешним шрифтом, скриптом или запросом при открытии.
- Передавать статус одним цветом или значком.
- Писать число без источника и знаменателя; заменять нехватку данных нулём.
- Править готовый HTML в обход генератора.
- Считать поверхность принятой по отчёту автора или по зелёной сборке.
- Менять неизменяемый исходник ради оформления.

## Результат

Строка в реестре с владельцем и ролью; страница, которая открывается офлайн и проходится с
клавиатуры; у каждого числа указан источник и знаменатель; в отчёте о сдаче — команды проверки
с выводом и заключение независимого рецензента по точному диффу.
