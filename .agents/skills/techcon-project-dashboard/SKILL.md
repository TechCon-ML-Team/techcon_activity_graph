# Дашборд проекта: числа с происхождением, новая версия — новый файл

## Когда

Ты собираешь или меняешь дашборд, срез или сводку статуса проекта, где читатель принимает
решения по числам. К исходным данным проекта (замерам, отчётам, записям) скилл не относится:
их не правят ради красивого дашборда, дашборд только читает их.

## Шаги

1. **Найди первичный источник каждого числа** до вёрстки. Производный файл (HTML, сводный
   JSON) руками не правится: правится источник или сборщик, потом файл пересобирается.
2. **Опиши число записью** в файле данных, отдельно от вёрстки. Обязательные поля:
   значение, единица, знаменатель («из скольких»), источник (файл, команда, запрос),
   дата среза. Нет любого поля — числа на дашборде нет.
3. **Отметь отсутствие данных явно**: значение `null` и причина («не замерялось», «источник
   недоступен»). Ноль — это замер, который дал ноль. На странице «нет данных» выглядит иначе,
   чем «0»: другой текст, полый маркер, пунктир на графике.
4. **Покажи конфликт источников**, а не выбирай победителя молча: обе величины, их источники,
   кто отвечает за разбор и следующее действие. Победитель выбирается только по основанию,
   которое записано рядом (например, «замер свежее», «источник первичный»).
5. **Не смешивай оси**: рубли с процентами, штуки с долями, разные периоды в одной шкале.
   Разные знаменатели рядом — только с подписью каждого. Ось не с нуля — только с явной
   пометкой «шкала начинается с N».
6. **Собери одной командой** из файла данных. Сборка детерминирована: без текущего времени в
   тексте, без случайного порядка, с сортировкой ключей. Дата среза берётся из данных.
7. **Проверь детерминированность**: собери дважды, сравни результат побайтно. Различие — дефект
   сборщика, а не «допустимая погрешность».
8. **Выпусти новую версию новым файлом** с датой или номером в имени. Писать её нужно с нуля
   из данных, а не правкой предыдущей: правка накапливает хвосты отвергнутых решений. Прежние
   версии не трогаются, не переименовываются и не удаляются.
9. **Прогони проверки** (раздел ниже) и только потом показывай владельцу или читателям.

## Два слоя читателя

Дашборд читают двое, и это два разных текста.

- **Пользователь** (руководитель, коллега из производства): простыми словами, без имён
  внутренних систем, без идентификаторов задач и коммитов, заголовок — сделанное, а не
  признание промаха. Только то, что помогает решить.
- **Разработчик**: источники, команды пересборки, идентификаторы, схема данных, журнал
  конфликтов. Живёт в отдельном блоке или отдельном файле рядом с версией.

Пользовательский слой не ссылается на разработческий («см. файл X») вместо объяснения: он
самодостаточен. Разработческий слой не подменяет числа пользовательского — он их
обосновывает. Подробности и проверки — `references/01-vzglyad-rukovoditelya.md`.

## Проверки перед выпуском

- у каждого числа заполнены все пять полей записи (значение, единица, знаменатель, источник, дата);
- нигде «нет данных» не превратилось в 0 (поиск `null`-значений по итоговому тексту);
- метрика имеет смысл: если базовая доля явления близка к 0 или 100 %, процент вводит в
  заблуждение — такой показатель не публикуется;
- итоги пересчитаны сборщиком, а не набраны в тексте;
- повторная сборка даёт тот же файл;
- слова пользовательского слоя проверены по словарю языка (перевод везде, кроме кода и имён
  команд); нет пустых оборотов;
- в файле нет секретов, адресов машин и домашних путей;
- кодировка UTF-8, `<meta charset="UTF-8">` первым в `<head>`; числа с неразрывным пробелом
  U+00A0 (узкий U+202F на части телефонов рисуется квадратом);
- вёрстка: светлая и тёмная темы, широкие графики в контейнере с горизонтальной прокруткой,
  страница не прокручивается вбок; каждая графическая ячейка подписана и имеет подсказку.

Подробный порядок вёрстки и выпуска — `references/02-vyorstka-i-vypusk.md`.

## Запреты

- Править производный файл вручную вместо источника или сборщика.
- Показывать число без источника и даты «потому что все и так знают».
- Заполнять пропуск нулём, средним или значением предыдущей недели без пометки.
- Сглаживать конфликт источников до одной цифры.
- Оставлять на графике плато или тренд там, где нет замеров: пропуск рисуется как пропуск.
- Переписывать старую версию, «чтобы ссылки не ломались»: ссылки ведут на старое имя, новое
  — новый файл.
- Хранить отвергнутый компонент «на будущее»: убирай его вместе со стилями в той же версии,
  где он перестал использоваться.
- Выносить внутреннюю кухню (как собран срез, чей это отчёт, номера задач) в пользовательский слой.

## Результат

Новый файл версии, файл данных с записями чисел, команда пересборки, результат
повторной сборки (идентична) и короткий перечень проверок с отметками. Если хоть одна
проверка не пройдена, в отчёте скилла это первая строка, а не сноска.

## Чего скилл не закрывает

Достоверность самих замеров. Дашборд честно показывает то, что лежит в источнике; проверка,
что источник соответствует миру, — `techcon-fact-verification`.
